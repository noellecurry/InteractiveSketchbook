Nielsen’s 10 Usability Heuristics

Two Readings Overlap

The heuristic that I felt most aligned with the Chapter 1 reading was heuristic number 2: match between the system and the real world. Chapter 1 talked a lot about how you not only need to think logically as a design but also with the psychology of how humans think. To me heuristic number 2 was really speaking to this human-centered design, and both the article and chapter 1 talked about this idea of natural mapping. I understand it as using spatial awareness for immediate understanding, and the Nielsen heuristics is in agreement with that. Another heuristic that stood out to me that I thought aligned with the reading was heuristic number 7: flexibility and efficient use. Chapter 1 also talked about misleading signifiers and gave the example about pipes in the road actually being made out of rubber, so it is a perceived anti-affordance but giving passage to those who knew. So the 7th heuristic made me think of this when it said it is hidden from novice user so it is a shortcut for more experienced users.

Heuristics my project violates

The first heuristic I believe my project violates is number 3: user control and freedom. The issue with my project is that there is no clearly marked “exit sign” for my users to stop the interaction. So, on the first screen where the user sees the title, instructions, and button; if the user is still reading the instructions and accidently clicks the button they would want to go back right away. They could do this my just clicking the “mircoProject” link in the nav but to a novice user they would not know that so I think my project could benefit from having a signal to the user where to click if they want it to stop and return to the first screen.

The second heuristic I think my project violates is heuristic number 5: error preventions. I think that this heuristic connects to the first heuristic I mentioned because the article explains to prevent mistakes supporting the undo and warns users if they are about to cause an error. Again I think this comes up in my micro project when user presses the interaction, and there is no signifier for them to stop the interaction and return to the previous page. I am not sure if an error could occur if the user starts pressing random keys or things on the website but that is something for me to keep in mind for upcoming projects.

Sketchbook Interface Audit

I think the heuristic that sticks out to me most that my overall sketchbook violates is number 1: visibility of system status. I realize that when I go through all the pages on my website, there is no indication of what page you are actually on. For example, for my pages called “number 1 – number 9”, it is confusing because there is nothing on the page that says number 1 and the nav does not turn a different color to signify that you are on that page. I think it is a small detail to me but for someone seeing my website for the first time would really help their experience.

The Hardest Heuristic

To me the hardest heurist is number 9: Help Users Recognize, Diagnose, and Recover from Errors. I think it is difficult for me to understand from a technical standpoint because I am not sure how I would do that. After watching the video, the article provides I understand this heuristic better and an example in my own work could be if something does go wrong with one of pages, have a quick link that takes you directly to the home page.
