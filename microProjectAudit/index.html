Micro Project Audit

Visibility of System Status

I do think my page does a good job at the visibility system status because it has a title, instructions, and a clear button for a user to start the exercise. I also do think it is obvious what the interaction is because of the button and when it is pressed it immediately takes user to the breathing exercise.

Affordances & Signifiers

On my micro project, the action that is signified on this page is the “Breath Deep” button that the user will press to start interaction. An interactive affordance on this project that is unclear is the sound that plays during the interaction. There is nowhere in my instruction or signifier that there will be sound during the interaction. Another action that is available but unclear is to exit and start over the interaction for the Micro Project is clicking it again in the nav.

Navigation & Mapping

The relationship between the input and outcome on my Mirco Project is intuitive; I believe this is because it follows conventions for users. Users read instructions and then click on the button and immediately the interaction starts. I believe the user will misinterpret the interaction when it comes to the audio aspect of the interaction because there is no signifier that shows the user that affordance is there.

Constraints & Assumptions

One assumption that I made as a designer is that I assumed that users would know that when the sound icon appears on google chrome tabs, they would know to turn on their volume. This was an assumption because I used that people would be using google chrome and understand that when the sound icon appears they will know what to do. I believe this violates both chapter 1 reading and Nielson’s 10 Heuristics because it leaves users to guess, and the design is unclear.

Heuristic Violations

The first heuristic I believe my project violates is number 3: user control and freedom. The issue with my project is that there is no clearly marked “exit sign” for my users to stop the interaction. So, on the first screen where the user sees the title, instructions, and button; if the user is still reading the instructions and accidentally clicks the button, they would want to go back right away. They could do this by just clicking the “mircoProject” link in the nav but to a novice user they would not know that so I think my project could benefit from having a signal to the user where to click if they want it to stop and return to the first screen.

The second heuristic I think my project violates is heuristic number 5: error preventions. I think that this heuristic connects to the first heuristic I mentioned because the article explains to prevent mistakes supporting the undo and warns users if they are about to cause an error. Again, I think this comes up in my micro project when the user presses the interaction, and there is no signifier for them to stop the interaction and return to the previous page. I am not sure if an error could occur if the user starts pressing random keys or things on the website, but that is something for me to keep in mind for upcoming projects.
